# LS-DYNA d3plot 数据读取与网页端渲染 —— 完整技术文档

> 项目：隧道爆破数字孪生可视化平台
> 数据源：LS-DYNA 求解器输出的 d3plot 系列二进制文件（3 个算例：光面爆破、预裂爆破、PBM-SPH-FEM 粒子爆破）
> 交付物：`工作区/webapp/`（纯离线单页应用，零外部依赖）

---

## 0. 总体架构

```
LS-DYNA 求解器
   │  d3plot / d3plot01..NN （二进制，64位字）
   ▼
Python 提取层 (extract_web_data.py / extract_sph.py)
   │  ① 解析 .k 关键字文件（节点/单元/材料/起爆定义）
   │  ② 逆向 d3plot 头部控制区 → 推算各数据块偏移
   │  ③ 逐状态读取场数据 → 物理量换算 → 空间验证
   │  ④ 量化编码（uint8/asinh/log）→ 打包自定义二进制
   ▼
webapp/data/*.bin + cases.json        （共约 90 MB，本地 HTTP 服务）
   ▼
浏览器渲染层 (index.html, 原生 WebGL + Canvas2D)
   │  ① fetch → TypedArray 零拷贝切片
   │  ② 四边形网格(结构云图) + 点精灵(粒子云) 双通道
   │  ③ 顶点着色器传场值标量 → 片元着色器色图映射
   │  ④ 时间轴动画 / 自动增益 / 剖切 / 三算例切换
   ▼
数字孪生风格仪表盘
```

设计原则：**重活（解析、量化、平滑）在 Python 一次性完成；浏览器只做"切片 + 上传 + 着色"**，因此 90 MB 原始结果能压缩到每算例 8~30 MB 的帧数据，且动画时每帧只需上传 1~9 MB 顶点数据。

## 1. d3plot 二进制格式基础

### 1.1 字与字节

LS-DYNA（R9.8，64 位版本）写出的 d3plot 以 **8 字节为一个"字"**（32 位版本为 4 字节——判别方法：把文件按 int32 读出，若有效数值每隔一个出现（夹着 0），即为 8 字节字）。字节序为**小端**。

整型数据按 `<i8` 读，实型数据按 `<f8` 读。文件**没有任何记录标签**——不是"类型+长度+数据"的块结构，而是**纯顺序布局**，所有偏移必须由头部控制区的参数推算，或用数据指纹定位。

| 10 | 运行时刻 | 运行时刻 | Unix 时间戳 |
| 11 | 1 | 1 | 文件类型（1=d3plot） |
| 12–14 | 版本 | 版本 | |
| 15 | ndim | ndim | 空间维数（实测为 4） |
| **16** | **numnp** | **numnp** | 节点数 |

## 2. 几何段（基文件 d3plot）

基文件只含几何与初始信息，不含状态。以 sph-1 为例（光面/预裂布局相同、头更短）：

```
[头部 268 词]
[节点坐标  3·numnp        ] ← 内部节点序（场主序：x1,y1,z1,x2,y2,z2,…）
[单元连接  9·nel8         ] ← 每单元 8 个节点内部索引(1基) + 1 个材料号
[narbs   ≈ numnp+nel8+31 ] ← 内部序→用户ID 映射（node_ids + elem_ids）
[Part 标题等]
```

- **节点内部序 ≠ .k 文件书写顺序**：求解器会重编号。提取器用 `.k` 中已知坐标三元组（如首个节点 (100,−30,−200)）在基文件中做**精确浮点匹配**定位坐标块起点，再以"SPH 粒子坐标序列 (29,−29,−1)(29,−27,−1)…"匹配出 SPH 节点在内部序中的起始索引（=FEM 节点数 626,714）。
- **单元连接**直接从基文件读（比解析 102 MB 的 .k 快一个量级），材料列用于区分 FEM Part；SPH 案例中每个 SPH 粒子在 .k `*ELEMENT_SPH` 中带质量 21.6 g，与状态记录 w25 一一对应。
- 光面/预裂的几何额外验证：基文件坐标块与 `.k *NODE` 逐点最大偏差 = 0。

## 3. 状态段（d3plot01…NN）

每个状态文件包含 1 个（SPH 案例）或 2 个（光面/预裂案例）时间步。**单状态字数（stride）由文件大小反推并算术闭合验证**：

### 3.1 光面/预裂（FEM-ALE 案例， stride = 9,445,006 词 ×2 + 208 尾）

```
[time 1]                                    ← float64，μs
[global nglbv=55]                           ← word0=动能KE, word1=内能IE, word2=总能量(=KE+IE✓)
                                              之后为逐材料能量数组
[节点坐标 3·numnp]  ← 场主序！注意不是每节点 9 词
[节点速度 3·numnp]
[节点加速度 3·numnp]
[单元数据 nel8·31]                          ← nv3d=31 词/单元
[Part号数组 nel8]                           ← 每单元的 Part 归属（值 1..7）
```

**单元 31 词布局**（每单元，顺序与 Part 数组一致）：

| 词(0基) | 内容 | 验证依据 |
|---|---|---|
| 0–5 | σxx σyy σzz σxy σyz σzx | 远场≈0，爆点附近量级合理 |
| 6 | 有效塑性应变 | 与损伤空间相关、单调增长至 1.45 |
| 7 | JH-2 hist1 | |
| **8** | **JH-2 损伤 D** | ∈[0,1]，高应变单元 D=1，ASCII 空间图为炮孔为中心的损伤带 |
| 9,10 | hist3,4 | |
| 11–16 | 塑性应变张量 εp（w11≈−w12，塑性体积不可压） | |
| 17–30 | 0（ALE 扩展位） | |
| 31 | — | |

> ⚠️ 注意 word11 **不是压力**（曾误判）——压力用 **p = −(σxx+σyy+σzz)/3** 从应力张量派生（JH-2 的 EOS 压力即静水应力），空气单元 σ=−p·δ 直接给出 1 atm 验证值 −1e-6 Mbar。

**节点块为场主序**（先全部坐标、再全部速度、再全部加速度）——这与"每节点 9 词"的直觉不同，是本次逆向的关键发现之一（两种布局文件大小相同，通过 SPH 案例的坐标指纹才区分开）。

## 4. 偏移定位与验证方法学（逆向核心）

d3plot 无标签头，所有偏移靠**指纹验证**确定，每种手段都要求物理自洽：

| 方法 | 原理 | 应用实例 |
|---|---|---|
| **已知坐标匹配** | .k 首节点坐标在文件中精确命中 | 定位基文件坐标块（光面@70、sph-1@268） |
| **物理常数指纹** | 材料初始密度/压力是已知常数 | 空气 ρ=0.0012、TNT 1.5、RHT 2.66 出现周期=记录长度 → SPH 记录 33 词 |
| **能量守恒定位** | word3 = word1 + word2 (TE=KE+IE) | 全文件扫描锁定所有状态起点 |
| **周期自相关** | 等长记录的等距匹配率峰值 | SPH 33 词/粒子（匹配率 0.698） |
| **文件大小算术闭合** | stride×状态数+尾 = 文件字数，残差=0 | 光面 208 词尾、sph-1 497 词尾 |
| **空间分布验证** | 物理场必须集中在爆点/结构面 | 损伤 D 极值位置=起爆坐标 (±100,225) 等 |
| **交叉源对照** | .k / d3hsp / 基文件三方互证 | 节点数、单元数、粒子数、材料参数 |
| **ASCII 网格打印** | 把场按质心投到 100×46 网格字符化 | 肉眼确认损伤带 V 形形态 |

每次确立一个字段映射，都必须通过至少两条独立证据（如"word8=损伤"由①值域[0,1]②高应变单元 D=1③空间形态三项共同确认），杜绝巧合匹配。

## 5. 量化编码与数据打包（现行：v3 容器 / schema 2）

> **2026-10-22 更新**：legacy 的 `uint8 + asinh` 打包已随 `webapp/data/` 下线。
> 现行口径 = **字段表精度（u2/f4/u1）+ 每帧独立 zstd 块 + 帧索引 + `globals_all`**；
> 权威定义见 `config/field_spec.json` 与容器 `frames.header.fields[]`。

### 5.1 字段精度与解码

| dtype | 写入 | 读出 | 适用 |
|---|---|---|---|
| `u2` | `raw = clip(round((v-offset)/scale), 0, 65535)` | `v = raw*scale + offset` | 位移/损伤/应变/压力/速度/加速度/粒子标量 |
| `f4` | 原值 `float32` | 直读 | 六分量应力 `stress`、`hist`、`pbm_pos` |
| `u1` | 1 bit/单元（LSB 优先） | `byte=idx>>3, bit=idx&7` | `active_mask` / `pbm_active` |

- `scale=(全帧 max-min)/65535`、`offset=全帧 min`，由转换器**两遍扫描**确定并写入 `frames.header.fields[]`。
- `--precision f4` 把除掩膜外全部字段改为 `f4`（无损）；`--precision u2` 为显式量化，`stress/hist/pbm_pos` 仍 `f4`。

### 5.2 帧块与索引

```
D2W3F | header_len(u32) | header_json | padding(header_reserve=1 MiB) | frame_blocks | globals_all
```

- 帧块区起点 `frames_base = 9 + header_reserve`（与 header JSON 实际长度无关）。
- `frames[i] = {offset(绝对字节), len(压缩后), usize(解压后=frame_bytes)}`；`codec='zstd'` 时每帧是独立 zstd 帧，HTTP Range 可直达。
- `globals_all` 为 `f8[nframes, nglbv]` 独立块，`offset` **相对 `frames_base`**（与 `frames[].offset` 的绝对口径不同）。
- 前端用 `lib/fzstd.js` 解压，再按 `fields[]` 的 `dtype/scale/offset` 解码。

### 5.3 位置数据

- 位移：`u` 为节点相对首帧坐标的差值（`u2` 或 `f4`），**不再做 int8 量化**；大变形显示端有 20% 对角线硬上限。
- SPH/PBM 粒子：`pos0` 与逐帧 `pbm_pos` 为 f4；粒子节点集合用 `particles[].nodes`（未被实体单元引用的节点索引）。

### 5.4 网格预处理

- **外表面提取**：每个单元 6 面 → 4 节点排序 → `np.unique(..., return_counts)`，出现 1 次即外表面；附带 `owner_elem` 用于场着色。
- **剖切**：按 `conn` 做单元级 CSG + 封盖（`applyLayerCut`），不再使用旧版“剔除质心”的做法。
- **节点平滑**：损伤/应变/vm 走单元→节点体积加权；压力/密度保持原始以保住波阵面；`--field-location element` 时直接单元值（与 LS-PrePost 单元云图一致）。

## 6. 浏览器端渲染技术

### 6.1 数据装载

- `fetch` + `arrayBuffer` → `DataView` 读尾部计数 → **TypedArray 零拷贝切片**（`subarray`/构造器视图，不解码、不复制）；
- 第三算例（54 MB）**惰性加载**：首次点击 tab 才拉取，加载期间显示遮罩提示；
- 服务器发送 `Cache-Control: no-store` 避免迭代开发时新旧文件混杂。

### 6.2 结构云图（四边形通道）

- 每个可见面 = 4 顶点 + 2 三角形（uint32 索引，WebGL1 需 `OES_element_index_uint` 扩展，WebGL2 原生支持）；
- 顶点属性：`aPos`（静态初始坐标+剖切 z）、`aDisp`（每帧位移，f32×2）、`aField`（每帧场值标量，f32×1）、`aKind`（材质类别 1/2/3）；
- **每帧只上传 1 个标量/顶点**（139,026 面 ≈ 2.2 MB），而非 RGB（6.7 MB）——CPU 端零色图计算；
- **色图在片元着色器内实现**：7 段 turbo 彩虹与 5 段蓝-红发散两套 GLSL 多 stop mix，`uDiv` uniform 切换；剖面封盖/背景降噪用 `uGreyR/uGreyA`（按 aKind 向灰色 mix）。

### 6.3 粒子云（点精灵通道）

- `gl.POINTS` + 顶点着色器 `gl_PointSize = uPtScale / gl_Position.w`（透视尺寸衰减，clamp 1.5–9 px）；
- 片元用 `gl_PointCoord` 画圆形软边精灵（smoothstep 边缘+透明度渐变）；
- 位置与场值缓冲每帧 `bufferSubData` 流式更新（SPH 578 KB + PBM 432 KB）。

### 6.4 交互与动态效果

- **自动增益**：每帧统计场最大字节值，显示值除以帧内占比——任何时刻波前都满对比度，图例刻度同步缩放（可开关）；
- **材质联动**：看空气超压时，岩石同步显示自身应力波（压力场、帧内归一化、亮度 0.9）——空气冲击波与岩石应力波同屏传播；
- **时间轴**：12 关键帧等步进播放 + 滑块跳转 + 全时程能量曲线（KE/IE 提取自全部 87/102 状态的 global 块）上的时刻游标；
- **起爆时序**：光面/预裂按延期分级点亮炮孔标记（五级 0–400 µs），PBM 案例面板实时绘制产物粒子 XY 散点；
- **视图预设**：倾斜 / 俯视平面 / 聚焦爆区；鼠标拖动旋转、滚轮缩放、右键平移（自实现 mat4 MVP）。

### 6.5 稳定性措施

- 无标签二进制 → 所有偏移经验证后才写死；数据管线用独立 node 脚本（`validate_*.js`）复核布局/尺寸/解码值；
- 页面逻辑用 **DOM/WebGL 桩冒烟测试**（`smoke_test.js`，Proxy 模拟 document/gl/fetch）在 node 中完整重放 boot→切案例→遍历帧×场，无需浏览器即可回归；
- 服务器发送 no-store 头，避免迭代时浏览器缓存旧文件。

## 8. 已知边界与后续方向

- PBM 记录个别字段（w0、w11、w26、w32）语义未完全定论（推测为燃烧分数/内能类），当前仅用于归一化着色；
- sph-2（47,641 粒子 + 94,423 单元，无 .k）与 blasting in air（纯 ALE）两算例可用同一套方法接入；
- 损伤等值线平滑为 2 轮拉普拉斯，若需保真可加"原始/平滑"开关；
- 光面/预裂的节点块为场主序这一结论对其他 LS-DYNA 版本未必成立，接入新算例时需用坐标指纹重新验证。
